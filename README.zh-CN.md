# ThesisLedger

### 给自己搭一套投资研究工作台

ThesisLedger 是一套开源的个人投资研究工作台，可以部署在自己的电脑上。你可以把整理好的公司资料、研究判断和估值假设放进本地工作区，之后对照新披露查看变化，并留下为什么修改观点的记录。研究流程由你安排；需要时，也可以另选一个自己熟悉的 AI Agent，配合工作台查找资料、核对口径、试算情景。

**怎么用好 AI Agent 来帮你投资？** 先把自己真正想弄明白的问题告诉它，也说清你熟悉什么、最不确定什么。让 Agent 沿着公司的经营过程找依据、查缺口、找反例、试算情景；再回到原始材料核对数据和出处。你的行业经验能帮你找到值得追问的地方；哪些解释站得住，还要看证据。新披露也可能让原来的判断需要重来。

## 先从一个判断开始

假设你觉得天然气需求增长，可能让生产商更值钱。这个想法可以作为研究起点，却还不能直接推到“公司会多赚多少”或“每股价值该是多少”。需求落在哪个地区、公司能不能把产品送到买家手里、实际售价受什么影响、扩大产量要花多少成本，每一步都可能改变答案。

你可能熟悉这个行业，知道管道、加工能力或长期合同会影响公司能否把需求变成收入。把这些背景告诉 Agent，它就能把注意力放在你认为关键的地方。你的经验帮助提出问题，随后仍要查材料：公司有多少可用能力？合同如何定价？扩建需要多少资本？哪些信息还没有披露？

可以把研究链条先画成这样：

```text
行业需求 → 公司能否承接 → 可售产量与实际售价
        → 成本与再投资 → 可用现金 → 每股价值
```

请 Agent 顺着这条链逐步说明依据和缺口。若它从“行业需求增长”直接跳到“公司受益”，就让它补上中间环节。资料回答不了的问题先留作未知，往往比编出一个看似精确的数字更有用。

## 把你的经验变成 Agent 能检查的问题

“分析一下这只股票”没有告诉 Agent 你究竟在判断什么。可以从一个暂时的看法说起：你觉得什么变化可能影响公司？为什么你认为它重要？哪些部分来自自己的经验，哪些只是还没核实的猜测？眼下最没把握的又是什么？

例如：

> 我觉得天然气需求增长可能改善这家公司的现金流，因为……我熟悉的是……最不确定的是……请从需求开始，查到公司可售产量、实际售价、成本和再投资，再看这些变化会怎样影响现金流与每股价值。重要数据请给出原文出处、期间、单位和口径；如果证据不足，请指出缺口，并找出最可能推翻我看法的材料。

这样的交代既给 Agent 一个明确任务，也保留了你的判断从哪里来。Agent 可以帮你扩大查找范围、比较材料、提醒你漏了什么；你还需要判断这些问题是否切中公司的业务，以及它给出的材料是否足以支持结论。

## 引用是查找原文的线索

看见一个数字，先核对公司主体、对应业务、报告期间、单位和统计口径。同样写着“产量增长”，可能一个是日均产量，一个是年度总量；也可能期间里发生了并购，比较的业务范围已经不同。口径没有对齐，计算再准确也可能回答错问题。

再看这句话属于哪一层：公司披露了什么事实？你怎样解释这些事实？模型又为了推演未来作了哪些假设？例如，销售额增加是披露结果；认为增加来自竞争优势，是一种解释；假设这种优势还能持续几年，则是模型假设。三者都可能重要，但要分开记录，才能知道结论究竟依赖什么。

Agent 给出的链接只是回到原文的入口。打开材料后，确认原文真的支持这句话，也确认资料在当时已经发布。引用完整，不等于结论正确；财报里的真实数字，也不会自动证明你对未来的解释。

## 让反面证据也进入研究

如果你已经看好一家公司，可以让 Agent 认真寻找最有力的另一种解释。不要只要求它各写一段“看多”和“看空”，而要问：什么可观察的数据能区分这两种解释？如果你认为需求增加会推高售价，合同、地区价差或新增产能分别能说明什么？出现什么结果时，你会考虑修改原来的观点？

这一步把“我相信”变成了以后可以检查的判断。把支持材料、反例和未来观察点连同日期记下来，新的披露到来时就能对照。Agent 可以找到矛盾、整理证据；矛盾对公司经营有多重要，还要结合业务背景、投资期限和你自己的问题来判断。

## 模型适合回答“如果”，不负责把未知变成事实

模型能让假设之间的关系看得更清楚。你可以试试售价下降、资本开支增加或增长推迟时，收入、现金流和按当前假设测算的每股价值会怎么变。一次先改一个关键变量，再看中间计算过程，通常比盯着一个最终数字更能说明问题。

ThesisLedger 的 EXE 案例可以把 **Realized price（实际售价）** 从 3.5 调到 4.0 USD/Mcfe，观察收入、现金成本、资本开支和 FCFF 如何变化。这个结果是在其他设定暂时不变时的情景推演。案例采用有限预测期、零期末价值等简化前提，也没有补齐融资、套保和稀释分析；它用来展示怎样查输入、跑模型和检查结果，不是完整估值。

同一份输入和代码能重算出相同结果，说明这次计算可以复现。它不能证明输入资料完整、假设合理，或模型已经覆盖公司的所有关键因素。小数位数再多，也不会让没有依据的假设更可靠。

## 再问一层：当前股价隐含了什么要求？

一组情景估值告诉你，在给定假设下可能得到什么结果；它没有告诉你市场价格已经预设了什么。对支持的工业企业和经常性收入模型，如果你提供带日期的股价，工作台可以在其余假设不变时，反推某项经营指标需要达到什么水平，再把这项要求放回正向模型核对。

这是一个有条件的计算：其他输入都暂时固定，一项指标也不能解释市场对公司的全部预期。它可以帮你把“看起来贵或便宜”变成更具体的问题，却不能证明公司会做到那个水平。EXE 商品案例目前没有提供股价，也不支持这项反向求解。模型范围和限制见[研究方法](docs/METHODS.md)。

## 提醒来了，回头检查哪条判断受到了影响

新公告本身不是利好或利空结论。先打开原文，确认它新增了什么信息，再问它影响了研究链条里的哪一环：实际产量变了、合同或成本假设变了，还是新闻只是在转述此前披露？

对已关注的公司，符合条件的重大研究事件才会生成本地提醒；其他事件也可能留下记录，但不一定触发提醒。提醒不会改动已经采用的研究基线。你核对资料、提出更新、查看前后差异并明确接受后，新假设才会进入基线。这样下次复盘时，还能看见结论是由哪份资料、经过哪些改动而来。

## 给预测留一份当时的记录

预测期开始前，把预测值、采用的假设和日期存下来。等有了可核对的实际结果，再按同一口径比较。旧预测要保留下来，不能在结果出来后悄悄改写。

工作台可以冻结预测批次、保留旧版本，并在你提供后续观察值后进行比较。复盘时也要把结果和过程分开：结果好，可能碰上了运气；结果差，也可能是当时无法预见的变化。一次预测说明不了投资能力，但完整记录能帮你发现自己常在哪些假设上偏乐观，或总漏掉哪一类经营约束。

## 把研究方法放进自己的工作台

ThesisLedger 默认在本地运行，面向单人研究。每家公司可以有自己的资料、研究观点、模型输入、证据、事件提醒和运行记录。你可以直接跳到自己的公司，也可以先打开 EXE 案例看看工作台和研究流程。

自有资料要按[输入约定](docs/DATA_CONTRACT.md)整理成结构化 JSON，包含公司基线、模型假设和带来源的证据。导入器不会把 PDF、Excel 或随手笔记自动转成可用数据，也不会替任意上市公司抓取并补齐完整财报。当前模型支持部分工业企业、经常性收入业务和有限范围的商品生产商；其他业务类型需要增加模型适配器。

你可以在工作台之外使用自己熟悉的 AI Agent，按[协作指南](agents/START_HERE.md)准备公司数据和事件记录。工作台内置的四工具审阅流程目前只接通 EXE 案例；普通自建公司工作区的浏览器 **Model assistant** 尚未接通。托管 LLM 需要你自行选择并配置服务，实时推理尚未验证；启用时，选定的研究上下文会发送给所配置的服务商，使用前请检查资料。

## 把工作台跑起来

需要 Python 3.10 或更新版本。选一条适合自己的路径即可。

### 可选：打开 EXE 离线案例

案例不需要数据密钥、模型账户或第三方运行依赖：

~~~sh
python3 run.py case EXE
~~~

浏览器会自动打开。若没有打开，请访问 http://127.0.0.1:8765/#lab，进入 **Research Lab（研究分析页）**。修改 **Realized price** 后运行 **Run evidence review**，再选择 **Verify saved run** 检查已保存记录能否复现。

案例使用 Expand Energy 的 [2024 年](https://www.sec.gov/Archives/edgar/data/895126/000089512625000021/exe-20241231.htm)和 [2025 年](https://www.sec.gov/Archives/edgar/data/895126/000089512626000011/exe-20251231.htm)财报。2024 年的报告只包括 Southwestern 并购后的部分期间，2025 年则包括全年；报告口径不同，不能把产量变化直接当成有机增长或未来预测。其他模型范围与案例缺口见[案例说明](docs/EXE_CASE.md)。

### 直接导入自己的公司

准备好符合[输入约定](docs/DATA_CONTRACT.md)的 `my-company.json` 后，可以直接创建自己的工作区：

~~~sh
python3 run.py init --workspace .thesisledger/my-research
python3 run.py import my-company.json --workspace .thesisledger/my-research
python3 run.py serve --workspace .thesisledger/my-research --port 8766
~~~

导入会建立公司资料，不会覆盖现有基线。要更新基线，需要先提出候选修改、检查前后差异并明确接受。逐步说明见[使用指南](docs/USER_GUIDE.zh-CN.md)。

## 公告监测、SEC 和动态提醒

现成的公司官网监测目前只适配 EXE。它读取公告日期、类别、申报编号和链接，再生成本地提醒；不会下载完整财报、提取财务数字，也不会在后台自行运行。单次检查：

~~~sh
python3 run.py ir-watch EXE --once
~~~

持续检查需要在终端中主动启动进程。监测其他公司的网页需要另行适配；工作台也接受你自己的采集器生成的事件 JSON。SEC 的定期监测 `sec-watch` 目前也只支持 EXE。按 CIK 获取一次 SEC 公开数据快照使用独立的 `sec` 命令，这不等于已经接通该公司的持续监测。

### 关注自己选择的公司

先按[输入约定](docs/DATA_CONTRACT.md)导入该公司的研究资料。在 **Monitor & Timeline** 里为这家公司选择 **Focused tracking**、**Observe** 或 **Discover**，并打开 **Follow**。这一步只是把已导入的公司加入关注列表，不代表工作台会自动获取它们的公告。

要监测其他公司的公告或 SEC 文件，需要你配置或编写采集器，从选定的公开来源读取更新，并把每条待复核事件写成 JSON 放进事件目录。最小事件可以长这样：

~~~json
{
  "id": "ACME-2026-001",
  "symbol": "ACME",
  "kind": "ambiguous_evidence",
  "title": "新公告待核对",
  "source_document": "https://investor.example.com/filing",
  "published_at": "2026-01-15T13:00:00Z",
  "decision_ts": "2026-01-15T14:00:00Z",
  "verified": false,
  "summary": "发现新公告；先核对原文和报告期间，再判断是否影响研究。"
}
~~~

上面是结构示意，不能原样作为真实研究资料使用。把 `ACME`、事件编号、来源链接和时间换成你已导入公司的真实信息；时间应满足公告发布时间不晚于复核时间，复核时间不晚于当前时间且不早于已保存基线。`ambiguous_evidence` 表示“发现了材料，尚待核实”，不会提出模型更新。只有核实材料，并确认它对应当前模型支持的输入项后，才用 `driver_change` 记录变化。字段与事件类型见[输入约定](docs/DATA_CONTRACT.md#evidence-event)。

假设工作区已按上文创建，采集器把 JSON 放进 `./my-events/`，可以先手动检查一次：

~~~sh
python3 run.py monitor --workspace .thesisledger/my-research --events-dir ./my-events --once
~~~

需要持续检查这个目录时，可让命令每 15 分钟运行一轮：

~~~sh
python3 run.py monitor --workspace .thesisledger/my-research --events-dir ./my-events --interval 900
~~~

如果暂时不写采集器，也可以把人工核对过的公开材料整理成事件 JSON，再用 `--once` 导入。持续运行时，这个命令只扫描事件目录里的 JSON 文件，不会替采集器访问公司网站、SEC 或行情服务；采集器需要由你另行运行或安排定时任务。同一事件重复扫描会去重。公司已加入关注列表且事件达到提醒条件时，工作台才会生成本地提醒。更完整的来源、证据与事件字段说明见[数据约定](docs/DATA_CONTRACT.md)。

SEC 直连要在请求中声明真实的应用身份和联系方式，这不是账户注册或证件认证。v0.2.2 的验证记录曾遇到 HTTP 403，之后是否恢复尚未验证。无法直连时，可以从 Expand Energy 官网[年度报告页](https://www.expandenergy.com/investors/company-reports/)或[2025 年 10-K 文件页](https://investors.expandenergy.com/sec-filings/sec-filing/10-k/0000895126-26-000011)人工查看原始材料；当前程序不会自动下载或解析这些文件。身份信息如何填写及可用的替代路径，见[使用指南](docs/USER_GUIDE.zh-CN.md#向-sec-声明应用身份)。

## 隐私和项目边界

运行数据和 `.env` 文件已从 Git 忽略。导入器会拦截部分常见账户和凭证字段，但无法识别自由文本里的所有个人信息。个人资料导入前仍要自己检查；启用托管 LLM 前，也要确认将发送给服务商的研究内容。

ThesisLedger 不会替你交易。云端运行、托管 LLM 推理和实际邮件送达在 v0.2.2 中尚未经过验证。固定测试通过说明受检样例和流程通过，不代表任意公司数据提取准确、LLM 研究质量可靠或投资结果有保证。

v0.2.2 的验证记录包括 Python 3.12 和 3.14 各 162 项测试、3 项界面状态检查，以及 19 项固定公开案例检查。你可以在本地运行：

~~~sh
python3 run.py benchmark
python3 run.py evaluate
~~~
