# ThesisLedger

### 搭建自己的投资研究 Agent

ThesisLedger 帮助你理解如何与 Agent 一起做投资研究，并搭建自己的研究工作台。你用行业知识提出问题、解释业务，让 Agent 帮助整理证据、检验假设和执行计算，再依据可以核对的结果修正判断。

项目把这套配合方式写进文档，也做进可以运行和修改的工作台：一条数据如何得到确认，一个观点如何变成可检验的假设，一次计算如何被复核，新信息又如何改变原来的判断。读者可以沿着完整的研究过程，理解工具为什么这样设计，以及怎样把它用好。

## 带着自己的理解，把问题问具体

你可能已经形成了一个观点：“天然气需求增加，会让这家生产商更值钱。”你熟悉的产业链、竞争格局和企业经营，能帮助你找到真正值得研究的问题：公司能增加多少可销售产量，拿到什么实际价格，又要为增长投入多少资本？这些问题决定了 Agent 应该寻找什么证据。

主观判断在研究中有自己的位置，也需要说清依据。假如你认为公司有成本优势，可以让 Agent 比较同口径成本，并寻找可能解释差异的因素。较低成本可能来自经营效率，也可能来自资产结构或披露口径。你对业务的理解帮助解释差异，Agent 的比较工作则让原有判断接受检验。

合作可以从这样一段请求开始：

> 我认为需求增长可能改善这家公司的现金流。请围绕可销售产量、实际售价和新增资本投入整理公开证据，给出原始出处、期间和单位，指出最强的反证以及还缺什么。我们核对关键事实后，再讨论哪些假设适合进入模型、什么情况下需要修正这个判断。

你可以把这样的研究请求交给所使用的编程或研究 Agent。给它你的推理和疑问，让它帮助展开、核对并挑战。后面的计算和复核流程，再把这场讨论变成可以继续使用的研究记录。

## 把数据核对到它原来的语境里

Agent 返回一个数字时，打开它指向的原始财报或公司文件，找到对应的表格、注释和期间。确认公司与业务范围，再核对单位和定义。例如，同样写着“产量”，可能是单季总量、全年总量或日均值；同样写着“利润”，可能包含不同的调整。只有口径对得上，比较和计算才有意义。

看到收入增长，还要分清它来自价格、销量还是并购。财报中的收入变化是一条可核对的事实，把它归因于竞争优势是对事实的解释，预计这种优势明年还能持续则是一项预测假设。把这几步说清，数据才能支持推理，假设也能被单独讨论。

遇到冲突，先保留各自的来源和定义，再让 Agent 帮助解释差异。还要检查当时究竟有哪些资料可用：后来发布的数据可以用于今天的研究，但不能倒过来证明过去已经知道它。ThesisLedger 保存来源、期间、单位与时间信息，方便这类核对；内容仍需要你回到原文确认。

## 把经营故事接到股东价值

需求增长要先变成公司能够实现的销量，再通过实际售价变成收入。收入还要支付经营成本、资本开支和营运资金。走到这里，才知道增长能留下多少现金；结合现金、债务和股数，才能继续讨论每股价值。

```text
需求与竞争 → 可实现的经营活动 → 收入 → 成本与再投资 → 现金流 → 每股价值
```

这条关系解释了为什么一个看起来很好的增长故事，仍然可能需要更多研究。更高产量可能伴随更高资本开支，账面利润可能尚未收成现金，融资可能改变原有股东能分到的份额。情景推演要把这些关系一起带进去。

工作台保留中间计算，让你看见一个假设怎样传到结果。数据缺失、增长路径不可实现，或融资需求没有得到解释时，模型保留缺口。你可以沿着缺口继续研究，避免把没有依据的精确数字当作结论。具体公式和各类业务的适用范围见[研究方法](docs/METHODS.md)。

## 让 Agent 的判断能被检查

研究 Agent 需要同时处理两类工作。整理证据、指出矛盾、提出值得追问的问题，需要语言层面的理解；计算现金流、检查约束和重现结果，需要明确的输入与计算规则。ThesisLedger 把两者接起来，让建议能指回依据，让计算能回到输入。

这套协作方法可以指导你使用外部编程或研究 Agent。仓库内置的 Agent 则从较小的范围示范：按固定复核计划调用四个限定工具，基于已选资料给出带来源的建议。它的工具记录、输入和计算都可以检查；接入真实 LLM 工具调用是可选路线，目前尚未通过实时验证。

模型修改也有自己的复核过程：先形成具体候选，看清改动和计算结果，再明确接受。保存的运行记录支持离线重现。重现一致说明这次计算可以复现；证据是否可靠、假设是否合理，仍然需要研究者判断。

这些设计可以用于搭建自己的 Agent：把输入、计算、建议和接受修改的过程讲清楚，每一步都留下足够的依据，供下一次研究继续使用。[研究协议](agents/RESEARCH_PROTOCOL.md)说明了完整的方法，[Agent 指南](agents/START_HERE.md)提供了可以交给编程或研究 Agent 的开场请求。

## 新信息来了，先找它改变了哪一步

形成判断时，就给自己留下能够观察的修正条件。比如，需求增长的观点可能仍然成立，但如果公司扩产延迟、实际售价没有改善，或资本开支持续超出预期，原来对现金流的判断就需要重看。你可以让 Agent 主动寻找这些反证，再结合自己对业务的理解决定它们有多重要。

一份新财报可能支持原有判断，也可能只补充背景，还可能让最关键的假设失效。复核时回到原来的推理，找到信息改变了哪一步。同一条公告被多次转发，也只是一份证据。

因此，监测系统把新公告送进复核提醒。核对内容后，再决定是否提出模型更新。SEC 和 EXE 官网各自保留来源状态，同一份已验证公告会去重；来源故障也会留下记录。财报列表检查成功，不意味着新的财务数字已经完成核对。

本地工作台提供资料、推演、提醒和历史记录的查看入口。[自托管指南](docs/SELF_HOSTING.md)说明了如何部署到自己的服务器，以及邮件功能的配置路径。云端运行和实际邮件送达尚未验证。

## 留下当时的判断，才能从研究中学习

半年后回看一次预测，最有价值的问题是：当时哪项假设得到了支持，哪项出了偏差，偏差为什么发生？如果预测在结果出来后被改写，就很难回答这些问题。

ThesisLedger 在接受模型时保留旧版本和当时的预测。你可以在预测期限之后补入有来源的实际观察，再比较差异。这样的记录帮助你检查自己的判断习惯，也帮助你区分信息缺口、推理偏差和环境变化。

项目当前支持基于用户提供观察的预测比较，没有实现交易回测，也不以投资收益证明 Agent 的能力。[验证记录](docs/VERIFICATION.md)区分了计算、流程和实际运行各自得到的验证。

## 打开工作台

下载并解压仓库，或用 Git 克隆。在包含 `run.py` 的文件夹里打开终端，准备 Python 3.10 或更新版本。运行示例可以离线使用，不需要安装依赖、申请数据密钥或开通模型账户。

```sh
python3 run.py case EXE
```

浏览器会打开本地工作台。如果没有自动打开，访问 `http://127.0.0.1:8765/#lab`，进入 **Research Lab**。界面目前使用英文。

试着把 **Realized price** 从 3.5 调到 4.0 USD/Mcfe，观察售价如何经过收入、现金成本和资本开支，传到 FCFF 与条件性的每股价值。点击 **Run evidence review** 查看三条建议的依据和实际计算，再用 **Verify saved run** 检查这次运行能否重现。

滑块只影响当前沙盒，已有模型的修改需要另行确认。按 Ctrl+C 停止服务，再运行同一条命令会接着打开 `.thesisledger/exe-case/` 里的历史。

这个运行示例使用 Expand Energy 的 [2024 年](https://www.sec.gov/Archives/edgar/data/895126/000089512625000021/exe-20241231.htm)和 [2025 年](https://www.sec.gov/Archives/edgar/data/895126/000089512626000011/exe-20251231.htm)财报。它示范了业务范围变化、现金流口径和有限期推演如何影响研究。期末价值设为零，沿用带日期的现金与债务，股数使用年度 EPS 代理值。完整投资估值所需的融资、稀释、套保等分析仍有缺口，详见[案例说明](docs/EXE_CASE.md)。

## 接入自己的研究与监测

按[输入约定](docs/DATA_CONTRACT.md)准备核对过的公开或脱敏公司资料，在独立工作区导入。[使用指南](docs/USER_GUIDE.zh-CN.md#own-research)给出了步骤。内置模型支持工业、经常性客户收入和有限范围的商品生产商业务，其他业务需要相应的模型适配。

保持示例工作台运行，可以在另一个终端主动检查 EXE 官网：

```sh
python3 run.py ir-watch EXE --once
```

进入 **Monitor & Timeline** 或 **Alerts**，点击刷新查看结果。这条官网链路目前只适配 EXE，读取公告列表元数据。需要接入 SEC 时，按[身份声明步骤](docs/USER_GUIDE.zh-CN.md#sec-setup)填写真实的应用身份和联系邮箱。持续检查、暂停与恢复、访问故障的处理都放在指南中。

虚构公司演示 `python3 run.py demo` 还可以用来练习证据冲突、来源故障和模型确认，见[演示说明](docs/QUICKSTART.md)。运行数据和 `.env` 不进入 Git。已知私密字段会被拒绝，任意文字中的个人信息仍需要你在分享前检查。项目不执行交易。

## 实现与验证

运行时使用 Python 标准库、SQLite 和浏览器原生 JavaScript，没有第三方运行依赖。保存的研究运行包含选定输入、截止时间、工具决策、结果、配置和哈希；离线重现会核对代码版本和计算结果。

```sh
python3 run.py benchmark
python3 run.py evaluate
```

v0.2.2 的[验证记录](docs/VERIFICATION.md)包括 Python 3.12、3.14 各 162 项测试，3 项界面状态检查和 19 项公开案例检查。案例评测覆盖两份 EXE 财报的 16 条人工核对数据及 3 项流程检查，不代表其他公司的提取准确率、真实 LLM 的研究质量或投资收益。

EXE 官网链路通过过一次实时检查，并生成一条复核提醒。SEC 直连在返回已分类的 HTTP 403 后，尚未验证恢复。真实 LLM 调用、云端运行和 SMTP 邮件送达也尚未验证。
