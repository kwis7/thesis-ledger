# Contributing

Work in an isolated local workspace with invented/public-redacted examples. Run `python3 run.py evaluate` from the source checkout. Describe the concrete problem, resulting behavior and validation; preserve uncertainty and existing source lineage.

A new business model needs a causal revenue/cost/capital bridge, explicit units and claims, feasible connected scenarios, reverse back-substitution where appropriate and tests that can expose economic errors. A generic growth percentage is not a substitute for missing operating data.

A source adapter needs attributable documents, publication/retrieval/usable time, fiscal context, failure evidence, source rights and deterministic fixtures. Do not write inferred extraction output directly into accepted assumptions. A notification adapter needs distinct queued/attempted/accepted/failed/unknown states and no automatic retry of ambiguous outcomes.

Do not submit runtime databases, personal data, secrets or copied third-party material without appropriate rights. Git ignore rules do not protect already tracked files. Review screenshots and build artifacts before sharing. Publication, deployment and real external sends require the operator's explicit authorization.
